# 새 행사 알림

웹의 `/notifications`에서 알림함, 안 읽은 알림, 행사 구독 설정을 제공합니다. 로그인한 사용자는 행사 종류, 제목 키워드(1~50자), 주최 기관을 구독할 수 있습니다. 전체 행사 구독은 현재 지원하는 11개 행사 종류를 모두 구독합니다. 작업 일부가 실패하면 서버 목록을 다시 읽어 실제 상태를 표시합니다.

행사 상세의 ‘이 주최자의 새 행사 구독하기’ 링크는 해당 주최 기관을 미리 선택합니다. 구독은 기존 앱과 같은 계정의 구독을 공유하며, 웹에서는 행사 구독만 편집합니다. 채용 구독은 보존합니다. 새 행사 알림은 서버가 행사를 승인하거나 자동 승인할 때 발송되며, 이미 등록된 행사를 소급해서 발송하지 않습니다.

PC(화면 폭 1024px 이상, 마우스 포인터)의 행사 목록·상세에는 6초 뒤 왼쪽 아래에 작은 ‘새 행사가 올라오면 알려드릴게요’ 안내를 표시합니다. 배경을 가리거나 포커스를 이동하지 않으며 상세 패널 안에서도 버튼을 사용할 수 있습니다. 한 탭의 세션에서 한 번 표시하고, 닫으면 해당 브라우저에서 7일 동안 숨깁니다. 모바일, 권한을 차단한 브라우저, 이미 알림 연결을 마친 계정에는 표시하지 않습니다.

‘알림 허용’을 누른 방문자는 로그인 후 같은 행사 화면으로 돌아와 권한을 허용합니다. 로그인한 사용자는 버튼을 누를 때만 브라우저 권한을 요청합니다. 행사 구독이 없는 계정에는 전체 11개 유형을 구독하며 기존 행사 구독이 있으면 그 조건을 유지합니다. 전체 유형 등록이 일부 실패하면 계정별 재시도 표시를 저장해 빠진 유형만 이어서 연결합니다. 성공 안내의 ‘구독 설정’에서 언제든 조건을 바꿀 수 있습니다.

## Firebase 설정

Firebase 프로젝트 `duty-it`에서 2026-10-05에 생성한 웹 푸시 인증서의 공개키를 `src/lib/firebase/config.ts`에 연결했습니다. 기본 설정으로 배포할 수 있습니다. 다른 인증서를 사용할 때는 빌드 환경 변수로 공개키를 덮어씁니다.

```env
NEXT_PUBLIC_FIREBASE_VAPID_KEY=<웹 푸시 인증서 공개 VAPID 키>
```

덮어쓰려면 로컬에서는 `.env.local`, 배포에서는 빌드 환경 변수에 추가한 뒤 다시 빌드합니다. 이 키는 브라우저에 공개하는 키입니다. Firebase Admin 서비스 계정이나 APNs 비공개키를 넣지 않습니다. 기존 FCM HTTP v1 발송 기능을 그대로 사용합니다. 공개키 설정을 제거한 경우에도 알림함과 구독 설정은 동작합니다.

푸시는 HTTPS 또는 localhost에서 사용할 수 있습니다. iPhone/iPad는 iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 웹 앱으로 열어야 합니다. 알림 권한은 팝업의 ‘알림 허용’ 또는 설정의 ‘브라우저 알림 켜기’를 직접 누를 때만 요청합니다. 권한을 차단한 경우 사이트 설정에서 다시 허용해야 합니다.

## API 연결

| 웹 API | 기존 듀잇 API |
| --- | --- |
| GET `/api/notifications` | GET `/api/v2/alarms` |
| PATCH `/api/notifications/{id}/read` | PATCH `/api/v1/alarms/{id}/read` |
| PATCH `/api/notifications/read-all` | PATCH `/api/v1/alarms/read-all` |
| GET, POST `/api/subscriptions` | GET, POST `/api/v1/subscriptions` |
| DELETE `/api/subscriptions/{id}` | DELETE `/api/v1/subscriptions/{id}` |
| PATCH, DELETE `/api/notifications/device` | PATCH, DELETE `/api/v1/users/device/{token}` |

웹 API는 기존 HttpOnly 세션을 사용합니다. 변경 요청은 같은 출처를 확인하고 응답은 캐시하지 않습니다. 페이지 번호, 종류별 구독 입력, 토큰, ID를 검증합니다. 알림함은 행사와 채용 알림을 표시하며 필요한 제목과 기관 정보만 반환합니다. 구독 삭제는 현재 사용자의 행사 구독인지 먼저 확인합니다.

## 브라우저 푸시 수명

Firebase Messaging은 푸시 설정을 켜거나 이전 등록을 복원할 때만 불러옵니다. `/firebase-messaging-sw.js`는 설치된 Firebase 버전의 공식 SDK를 사용합니다. 서비스 워커는 푸시와 클릭 처리만 담당하며 개인 API 응답을 캐시하지 않습니다.

브라우저 토큰과 계정 ID는 버전이 붙은 로컬 저장소에 기록합니다. 인증 토큰은 저장하지 않습니다. Web Locks를 지원하는 브라우저에서는 여러 탭의 토큰 변경을 직렬화합니다. 같은 계정의 저장된 등록은 재접속 때 서버와 다시 동기화합니다. 초기 로그인 확인 중이나 일시적인 인증 연결 오류 때문에 등록을 지우지 않습니다.

푸시 끄기와 로그아웃은 해당 브라우저 토큰만 서버에서 제거하고 로컬 푸시 구독도 해제합니다. 한쪽이 실패해도 다른 쪽을 시도하며, 모두 실패하면 오류를 보여줍니다. 계정을 바꿀 때는 이전 로컬 구독을 해제한 뒤 새 계정에 등록합니다. 다른 휴대폰과 브라우저의 토큰은 변경하지 않습니다.

열린 탭에서는 새 알림 안내와 안 읽은 개수를 갱신합니다. 백그라운드의 notification 메시지는 FCM이 표시하므로 중복 표시하지 않습니다. 알림 클릭은 검증한 숫자 ID로 같은 사이트의 행사·채용 상세 또는 알림함을 엽니다.

현재 서버의 전역 `alarmSettings.push` 설정은 FCM 발송 단계에서 확인되지 않습니다. 이 구현은 웹 브라우저 토큰을 등록·해제하는 방식으로 해당 브라우저 수신을 제어합니다. 서버의 전역 설정 적용, 서로 다른 구독 종류의 중복 발송, 발송 재시도 정책은 별도 서버 작업입니다.

## 검증

`npm test`, `npm run lint`, `npm run build`로 API 연결, 입력 검증, 행사/채용 구독 분리, 로그아웃 해제 실패 경로, 서비스 워커의 중복 표시 방지와 안전한 클릭 경로를 확인합니다.

PC 팝업은 행사 목록, 직접 방문한 상세, 목록에서 연 상세 패널에서 확인했습니다. 비로그인 버튼의 로그인 복귀 경로, 전체 유형의 일부 등록 실패 후 새 탭에서 누락 유형만 재시도, 기존 키워드 구독 보존, 닫기 후 7일 숨김과 새로고침 시 재노출 방지, 390px 모바일에서 노출 제외도 확인했습니다. API 변경에는 격리된 테스트 계정만 사용했습니다. 최신 `main`을 반영한 상태에서 테스트 96개, 린트, 빌드를 통과했습니다.

2026-10-05 로컬 검증에서 PC·390px 모바일 화면, 구독 추가·해제와 오류 재시도, 개별/전체 읽음, 페이지 추가 로딩, 현재 페이지 밖에 미확인 알림이 있는 경우의 모두 읽음, 재접속 복원, 로그아웃 후 개인 화면 숨김을 확인했습니다. 구독·알림 API에는 분리된 테스트 데이터를 사용했습니다. 실제 Firebase 토큰 발급과 단일 브라우저 대상 시험 메시지의 foreground 수신 콜백도 확인했습니다. 알림 끄기와 로그아웃 뒤에는 서버 테스트 토큰, 루트 Push API 구독, 로컬 등록 기록이 모두 해제됐습니다. 운영 행사 승인에 따른 자동 발송과 실제 iOS 홈 화면 수신은 운영 테스트 대상으로 남습니다.

실제 수신 검증은 공개키를 설정한 뒤 테스트 계정에서 권한 허용 → 관심 행사 구독 → 해당 조건의 신규 행사 승인 → 열린 탭과 백그라운드 수신 → 알림 클릭 → 읽음 처리 → 브라우저 알림 끄기 및 로그아웃 순서로 진행합니다. 운영 행사 생성·승인과 운영 사용자 대상 발송은 별도 승인을 받은 테스트 범위에서 진행합니다.
